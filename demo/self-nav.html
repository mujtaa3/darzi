rung 1: the jail injection real data

The leak CSP cannot close — and the warden can

The widget below is fully jailed: opaque origin, no cookies, no storage, and default-src 'none'. It asks for your transactions — a granted, legitimate call — and then tries to mail them out two ways. Before rung 8 this page leaked real data. The attack code is unchanged; only the runtime is.

Run the listener first, because this page cannot be trusted to report on itself: python3 demo/exfil-listener.py. Only a server watching for the request can tell you whether bytes actually left.

  1. fetch() — a request. The widget's own CSP refuses it.
  2. location.href = … — a navigation. No directive in the widget's own CSP governs it. Only the embedder's frame-src does — so the runtime now embeds the widget in a frame it controls, the warden, whose frame-src 'none' stops the navigation before any DNS or TCP leaves the machine.
